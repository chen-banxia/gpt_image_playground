# 视频工作台使用与验证

## 配置与入口

顶部“图片 / 视频”切换工作台。打开设置，原图片 Key 标注为“生图 API Key”，视频区域单独填写 New API 根地址、豆包视频 Key、海螺视频 Key，然后点击“保存视频配置”。只有勾选“记住此 Key”才会在浏览器刷新后保留该视频 Key。

顶部语言按钮统一控制图片和视频工作台。视频表单、设置、校验、批量管理和下载提示均支持中文、英文，用户描述、分组名和素材文件名保持原文。两个桌面工作台的左侧面板顶部均与作品区操作栏顶部对齐，底部保留视口间距，提供更大的表单可用高度。

四个 Seedance 模型使用豆包视频 Key，`MiniMax-H3` 使用海螺视频 Key。各服务在设置中统一管理创建路径、查询模板和响应协议。默认地址为 `https://colorflowai.com`，默认路由如下：

- `POST {root}/doubao/api/v3/contents/generations/tasks`
- `GET {root}/doubao/api/v3/contents/generations/tasks/{id}`
- H3 创建：`POST {root}/hailuo/v2/video_generation`
- H3 查询：`GET {root}/hailuo/v2/query/video_generation/{task_id}`

请求使用网关 Bearer 令牌。豆包创建返回 `id`、结果为 `content.video_url`；H3 创建返回 `task_id`、查询结果为 `task.status` 和 `task.content.url`。生成过程中切换工作台或模型不会改变旧任务的凭证和路由。修改 Key 后，旧记录可在详情页明确重新授权查询，网关地址必须一致。

用户提供的 [海螺 V1 创建页面](https://apifox.newapi.ai/525593865e0) 对应旧系列。H3 的 [创建文档](https://apifox.newapi.ai/525593869e0) 和 [查询文档](https://apifox.newapi.ai/525593871e0) 明确采用 V2。只有部署显式把 V1 地址映射到 H3 协议时，才在 H3 设置中改成 `/hailuo/v1/video_generation`、`/hailuo/v1/query/video_generation/{task_id}`；修改路径不会把 H3 请求转为旧系列的 prompt / file_id 协议。

旧配置自动补上服务默认路径，保留自定义网关和已记住的 Key。新任务保存路由快照；老任务没有快照时仍沿用原 Doubao 查询路径，避免错误查询旧 ID。导出导入也保留快照。

失败卡片及详情新增“快捷重试”，直接使用原描述、模型、素材、分组和参数，以及当前保存的对应服务配置，创建一条新任务。原失败记录保留，新记录关联原任务，当前左侧草稿不被覆盖。快捷重试可能产生新的费用；提交结果未知或仍进行中的任务不提供此操作。提交期间禁用重复点击，缺失素材或 Key 时提示修复。

## 创作与素材

输入描述即可生成。默认首尾帧方式：无图片为纯文本请求；有首帧时添加 `first_frame`，尾帧为 `last_frame`。点击素材区的“更改方式”，按钮下方直接展开首尾帧与全能参考选项、说明及当前标记；选择成功后收起并更新素材区，也可按 Escape 关闭。短窗口会自动将选项滚动到可见位置。模式选择不再藏在下方高级参数中。

全能参考中的图片、视频、音频分别使用 `reference_image`、`reference_video`、`reference_audio`。已有素材切换时仍说明用途变化；切回首尾帧时明确选图，其他素材保留在参考草稿。高级参数保留声音、水印、返回尾帧等设置。

用户切换视频模型时，分辨率自动选择该模型支持的最低档：四个豆包模型为 480p，海螺 H3 为 768P，之后仍可手动选择更高分辨率。恢复草稿或复用任务参数时保留原分辨率；不兼容参数提示调整。Seedance 2.5 和 H3 首尾帧请求自动使用 adaptive，参考图片不套用该限制。H3 不发送未核对的声音、水印开关字段。

时长按上游规则限制：Seedance 2.0、Fast、Mini 为 4–15 秒整数，Seedance 2.5 为 4–30 秒整数，另支持智能时长；MiniMax-H3 为 4–15 秒整数，不支持智能时长。下拉仅列常用 5 / 10 / 15 秒，2.5 额外提供 20 / 30 秒，其余合法秒数通过“自定义时长”输入。常用档位不是上游唯一可选值。切换模型后不支持的旧值不列入选项，必须重新选择后才能提交。

已核对的豆包原生说明中，参考视频使用公网地址而非视频 Base64。当前本地参考视频会保存为草稿，但豆包提交时提示改用公网链接；海螺本地视频可在请求体限制内编码。若部署另有上传服务，可后续接入，当前不会把浏览器 blob 地址传给模型。

当前客户端保护边界（会在页面显示或错误提示中解释）：

- 图片支持 PNG、JPEG、WebP，文件不超过 20MB、短边至少 300px、比例在 2:5 与 5:2 之间。这是客户端保守输入范围，并不代表所有模型的最大能力。
- 本地参考视频、音频最多 100MB；实际模型还有更严格限制，音频最多 15MB，H3 视频最多 50MB。
- 2.0 系列和 H3 参考视频或音频的已读取时长为单段 2–15 秒、同类型总计最多 15 秒；2.5 放宽至 30 秒。公网链接无法从本地保证取得完整媒体元信息，最终仍由网关校验。
- 编码输入总长度保护上限 60MB；大素材改用公网链接。
- 描述长度保护上限 10000 字符。

这些边界失败会提示修复，不会静默丢弃素材、切换模型或改变生成方式。

## 历史与数据

视频使用独立 IndexedDB `gpt-video-playground`，图片保留原 `gpt-image-playground`。视频结果默认只存任务、URL、参数与下载标记，输入文件以 Blob 独立保存。图片卡片和详情里的“生成视频”会复制原图，清空图片历史不会删除已复制的视频输入。

支持共享分组、仅收藏、模型与状态搜索、已下载/未下载筛选、每页 15 条、本页多选、框选、批量归组、收藏、删除。未完成任务不算“未下载成品”；已下载只表示页面成功发起过保存或用户手动标记，不能识别外部另存为。

图片和视频现在共用作品工具栏、批量栏、分页和面板头部。分组与实际新作品归属单独一行，收藏、状态、模型、下载筛选顺序一致，搜索框提供清空入口。图片支持多成品的“部分下载”筛选；视频首版单成品不会匹配该选项。批量栏点击“下载”可选“打包 ZIP”“逐项下载”和“仅下载未下载文件”。两边都支持跳页按钮与回车，空结果仍显示分页。

视频设置可导出轻量 JSON 历史，或带输入文件的 ZIP 备份，也可独立导入。备份不含 Key 或生成视频文件。导入时可以选择恢复草稿，导入的远端任务需要重新授权后才查询。历史清理保留当前草稿；视频整体重置会清理视频草稿和文件，但保留图片、分组与配置。

## 下载

已生成的视频在列表进入可见区域时自动加载静止画面预览，保持暂停、静音，不自动播放。点击中间播放按钮再打开详情播放器。离开可见区、翻页或切换工作台会释放预览加载；预览失败显示提示，不改变生成状态或下载标记。预览使用浏览器原生视频解码，不依赖 Canvas 截图或 CDN 跨域读像素权限，也不把整个视频写入本地数据库。结果链接失效或编码不被浏览器支持时，可打开详情刷新链接或下载原文件。

单条下载、批量逐项和 ZIP 都仅拉取现有结果，不重新生成。第三方视频地址不携带网关 Authorization。失败项可单独重试；ZIP 部分失败时确认是否仅打包已取得文件，未包含文件不标记下载。

当前实现为有界内存下载与 ZIP，限制 256MB；已知大小先预检，未知大小按实际读取字节限制。超过限制提示减少打包数量或打开原视频下载，不提供无限流式写入。浏览器多文件下载限制、CDN CORS 和视频编码兼容性仍需由浏览器与部署处理。只打开原链接不自动标记下载。

## 同源代理部署

直接访问网关需要其 CORS 支持 Authorization 和 Content-Type。需要代理时，配置 `VIDEO_API_PROXY_URL` 为 New API 根地址（不含 `/v1`），前端勾选同源视频代理。前端填写的根地址须和部署目标一致。

开发环境 PowerShell 示例：

```powershell
$env:VIDEO_API_PROXY_URL = 'https://your-newapi.example.com'
npm run dev
```

Docker 通过同名环境变量配置，未配置时默认指向不可用的本机端口，避免意外连接其他服务。代理只允许 Doubao 与海螺 V1/V2 的创建 POST 和单任务查询 GET，客户端不能指定任意目标。其他自定义路径需部署端显式调整白名单。视频文件 URL 不经过该任务代理，因此它不解决 CDN 文件 CORS。

## 自动验证

```text
npm test
npm run build
```

新增的 `src/features/video/video.test.ts` 和 `downloads.test.ts` 验证模型 Key 路由、请求 JSON、参数/素材约束、独立 IDB、事务更新、未知提交、恢复授权、备份及下载标记。

浏览器回归脚本位于 `tests/video_workbench_browser.py`，需要 Python Playwright、Pillow 和已安装的 Chromium。先启动本地 Vite：

```text
node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 5174
python tests/video_workbench_browser.py
python tests/video_localization_browser.py
python tests/workspace_toolbar_browser.py
python tests/video_provider_retry_browser.py
```

可用 `VIDEO_TEST_BASE_URL` 覆盖地址。脚本使用独立无头浏览器上下文、模拟 New API 和浏览器生成的 WebM，验证三类生成请求、Key 路由、模式切换、草稿恢复、真实播放器、ZIP 文件、分页、批量删除、图片转视频隔离、导出无 Key 和手机布局。不会访问真实付费生成接口，也不会读取用户浏览器数据。

## 仍需部署账号验证

自动测试不能证明当前 New API 账号已开通模型。上线前应在明确预算下，分别验证五个模型的真实提交、完成查询和产物访问，尤其是 H3 海螺插件的启用与渠道权限、图片/音频 Data URL、参考视频地址及高级字段透传。创建与查询契约已参考 New API 的 Doubao 和 H3 专用文档，真实权限仍需用实际账号确认。
