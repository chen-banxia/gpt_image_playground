# 生图参数与预览升级

本次参考 CookSleep/gpt_image_playground 的 `1e9d5af`（v0.8.0）尺寸预设与透明背景实现，保留原项目 MIT 许可。不引入上游 Codex 模式限制：尺寸、质量始终作为接口参数发送。

## 默认值与迁移

- 默认图像模型：`gpt-image-2.5-sunburst`，默认质量：`high`。
- 首次升级会将旧默认 `gpt-image-2.5-flare` 配置切换为 sunburst，将输入栏的 `auto` 质量切换为 high。历史任务参数不改写；升级后仍可手动选择 flare 或 auto。
- GPT Image 2.5 模型提供 `auto / low / medium / high / xhigh / max`。切换至旧模型时，xhigh/max 归一化为 high。
- Responses 的文本模型使用 `model`，独立图像模型使用 `imageGenerationModel`，请求时传入 `tools[].model`。

## 尺寸

模型下拉支持 codex2api 的 `gpt-image-2-2k/4k`、`gpt-image-2.5-flare-2k/4k`、`gpt-image-2.5-sunburst-2k/4k` 六个超分别名。Images API 文生图和图生图均原样发送完整模型名。使用别名测试时请同时选择目标尺寸：显式 `size` 优先于模型后缀的默认档位；选择 `auto` 则交由网关决定。模型后缀表示网关后处理档位，不代表原生模型质量档位。

| 档位 | 正方形 | 16:9 | 3:2 |
| --- | --- | --- | --- |
| 1K | 1024×1024 | 1280×720 | 1536×1024 |
| 2K | 2048×2048 | 2560×1440 | 2160×1440 |
| 4K | 2880×2880 | 3840×2160 | 3456×2304 |

生图请求尺寸继续使用 16 倍数、最大边长 3840、宽高比不超过 3:1、总像素 655360–8294400 的约束。4K 正方形预设受总像素预算限制，使用 2880×2880。不会因 Codex 标志降至 1K，也不会把 size 改写成提示词。

### v0.3.1 精确自定义画布

尺寸窗口新增“最终尺寸处理”：

- **保留原图**：沿用原行为，按接口要求规整 size，输出上游原图。
- **精确 · 补边**：保留输入的精确宽高，等比例缩放，PNG/WebP 补透明边，JPEG 补白边；完整保留画面。
- **精确 · 裁剪**：保留输入的精确宽高，等比例填满画布，居中裁去超出的部分，可能裁掉主体边缘。

v0.3.3 恢复默认“保留原图”：指定尺寸和自定义宽高都不会自动启用本地补边或裁剪。2K/4K 模型别名的尺寸处理由 codex2api 完成，页面保存网关返回的图片。升级时仅将当前输入栏的尺寸处理重置为保留原图；之后仍可手动选择补边或裁剪，手动选择会正常记住。自动尺寸不执行本地缩放。

输入栏尺寸下方和任务详情均显示处理方式。已有图片与历史任务不会被重新处理；旧任务重试沿用其保存的参数，要使用新默认请从输入栏新建生成任务。

例如输入 `1920×1080` 并选择精确处理：任务保存的目标仍是 `1920×1080`，实际接口请求为 `1920×1088`，收到最终图后处理为 `1920×1080`。尺寸窗口会同时说明生图请求尺寸。预览帧不执行此处理，PNG/WebP 的透明背景会保留。

最终画布支持每边 1–8192 整数像素、总像素最多 16777216，无 16 倍数和宽高比限制。越界时禁止提交，不静默缩小目标。接口实际生图尺寸仍遵守前述约束。

结果元数据 `source_size` 记录本地缩放前解码出的尺寸，`size_fit` 记录补边/裁剪方式，`size` 记录最终文件尺寸。详情显示这些信息；`quality` 仍来自接口响应。本地缩放不等于 AI 超分或原生高分辨率，生成后不会自动再次调用模型。

最终文件解码后的真实像素覆盖接口声明的尺寸；质量仅取接口返回值，缺失时详情显示“未返回”，不把请求的 high 当作已验证结果。图片格式优先识别 base64 文件签名。

## 透明背景

输入栏背景选项有三种：默认、透明 · API 原生、透明 · 本地抠图。

- 原生模式向 Images 生成/编辑以及 Responses 图像工具发送 `background: "transparent"`。
- 本地模式在提示词中追加纯绿/洋红背景要求，收到最终图片后在浏览器中去除背景色；不会发送原生透明参数，也不会为此重新发起生图。
- 透明输出使用 PNG/WebP；从 JPEG 开启透明时自动改为 PNG。主动切回 JPEG 会关闭透明输出。
- 本地抠图适合贴纸和单主体素材，复杂发丝、半透明材质和接近背景色的主体可能有残留或误抠。中间预览展示尚未抠图的原始生成过程。
- 原生模式失败不会自动再生一张图片；可手动选择本地模式重试。

## 流式预览

- 在输入栏开启“生成预览”，发送 `stream: true` 与 `partial_images: 2`。默认关闭，兼容已有非流式服务。
- Images、编辑表单、Responses 均支持；多图任务并发单图请求，预览按请求编号分开展示。
- 支持 SSE 命名事件、CRLF、分片 UTF-8、心跳，以及兼容端点仍返回普通 JSON 的情况。
- 任务卡片和详情显示预览；预览只保存在内存，结束后清除。仅收到中间图后断流会报错，不保存为最终图片。不会在断流后自动重发生成请求。
- Nginx `/api-proxy/` 已关闭响应缓冲，部署时需要更新对应配置才能即时传递事件。
- 接口不支持流式参数时，可关闭预览继续使用普通模式。是否返回中间图由上游决定。

## 能力边界

客户端发送 size/quality/background 不代表 Plus 账号上游一定执行。保留原图模式显示实际尺寸差异；精确模式会在本地处理画布，并在详情标明处理前尺寸，不把放大结果标成原生 2K/4K。xhigh/max、原生透明与流式预览同样取决于当前模型、账号和反代版本。
